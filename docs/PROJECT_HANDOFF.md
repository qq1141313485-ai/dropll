## 2. 已确认的产品规则

- 首版不做登录、支付、评论或用户上传。
- 比赛资料、赔率浏览、选号和奖金计算均为信息计算功能；不产生真实出票或代购。
- “10000 倍”是计算倍数，必须与真实票面区分；首版不提供拆票/拆单入口。
- 多场选择单场仅在全部已选玩法支持单场时可用；复合过关、胆码、保存方案保留。
- 保存方案只存本机：最近 7 天、最多 200 条、无云同步。
- 计划内容只展示已获授权的来源图片，保留来源水印；无真实数据时显示空/失败状态，禁止演示数据。
- 未识别计划名称进入 `pending_name`，不得自动创建大量错误计划。
- 名称识别以低成本规则为主，OCR 仅处理有限的高价值兜底场景；不得因 OCR 消耗失控。
- App 不暴露同步、抓取、缓存等内部术语，异常提示面向普通用户。

## 3. 对话决策总表

### 3.1 选号与奖金

- 选号页不增加搜索、日期/联赛筛选、仅看已选、仅看支持单关等筛选工具；“更多玩法”和自动刷新不改。
- 顶部或底部持续显示已选场数、选项数、胆码数、最低过关要求和当前注数。
- 过关方式可选择复合过关；生成方案页的过关方式只展示，不能在该页二次修改。
- 比赛停售、接口暂时少返回或 SP 选项消失时，已选项不能静默移除，必须给出明确提示。
- 同场多玩法在组合计算中按市场软件的分支规则拆分；每个过关方式使用用户输入的同一倍数，不应臆测为平均分配倍数。
- “拆票”曾讨论过，但当前产品决定不做；不把没有实际出票意义的功能包装成出票方案。

### 3.2 比赛详情 UI

- 详情页的固定结构已定：`MatchHeader` 固定、`DetailTabs` 固定在头部下方、仅标签栏下方内容区独立纵向滚动；禁止改回整页滚动或 Sliver 吸顶。
- 固定头部的信息层级：联赛与场次、开赛时间、两队队徽与比分/VS、队名与比赛分钟；返回与分享按钮同导航层并避开灵动岛安全区。
- 详情页以 iPhone 15 Pro 的 Flutter 逻辑尺寸 `393 × 852` 作为主要像素验收基准；其他设备做响应式适配，不能把“所有设备逐像素相同”当作验收条件。
- 视觉基线为白底、深绿强调、紧凑数据表和细分割线；不使用大圆角卡片、重阴影或广告式模块。头部、标签高度、内容边距、表格列宽、字号和行高应以最终确认的真机效果逐屏验收。
- Android/Web 截图可用于核对信息结构和表格层级，但最终字体、安全区、间距和状态栏效果以 iPhone 15 Pro 真机截图为准；历史生图和第三方产品截图只作布局参考，不复制品牌、Logo、界面资产或未经授权内容。
- 未赛默认不展示“赛果”页；完场进入详情时默认展示赛果。详情页不提供“去选号”入口。
- “基本面”固定包含战绩、排名、状态、阵容、赛程五个二级栏目；缺少真实字段时隐藏对应内容或显示明确空态，不用占位数据补齐版面。
- 概览的正式模块顺序为：竞彩赔率、状态对比、历史交锋、重要缺阵。已存在 `_OddsSection`、`_FormComparisonSection`、`_HeadToHeadSection`、`_AbsenceSection`，后续应重构或修正它们，不再新增功能重复的第二套组件。
- 伤停只显示接口真实字段；没有具体原因时只能显示“伤病”“停赛”或“原因暂无数据”，禁止编造球员或伤停事实。
- 欧赔、亚赔、大小球是产品需要，但当前 API 契约明确尚未接入。没有独立、已授权数据源之前，不得用竞彩 SP 模拟这三类盘口。

### 3.3 数据、计划与 OCR

- 计划抓取优先保证“错分少于漏分”：陌生或多作者标题保持 `pending_name`，经规则或人工确认后再重跑。
- 多作者文章不得按图片顺序长期自动归类；图片级归属不足时保持待治理，不猜测拆分。
- OCR 不是默认通道。启用前必须有异常图片过滤、触发阈值、每日/每月调用上限、失败重试上限和成本记录。
- 队徽抓取/覆盖率是独立任务，先统计缺失、错配、下载失败和回退来源，再决定补齐策略。
- 比分“卡住”不能只看前端显示；必须区分上游未更新、服务端状态映射、实时链路断连和客户端缓存，并用接口与巡检记录验证。

### 3.4 备案、软著与合规

- 当前构建显示名为“球镜”，但备案最终是否受理、软著实名审核进度、最终上架名称均未在仓库中得到可验证的完成凭据，必须以各平台后台状态为准。
- 备案、安装包显示名、截图、隐私政策、支持页、软著和上架资料提交前必须一致；名称更改不等于备案或审核必然通过。
- 数据来源说明只能如实写公开只读 HTTPS 赛事/赛果/赔率资料及上游更新时间影响；不能把未授权数据写成自有数据，也不能承诺官方数据源。
- App Store 与各地区的赛事数据、彩票相关计算、营销文案与内容授权存在合规风险；发布前需要独立核对，不以技术实现替代合规结论。

### 3.5 官网、Web 与服务器边界

- 官网根目录与 Flutter Web 必须分开发布：官网为 `/www/wwwroot/cclloo.com`，Flutter Web 为 `/www/wwwroot/cclloo.com/app/`。不得将 Web 构建解压到官网根目录。
- API 是独立反向代理服务。部署官网或 `/app/` 时，禁止覆盖 API 配置、API 服务目录或下载目录。
- Flutter Web 必须保持国内网络可用：CanvasKit 和 Noto Sans SC 使用站内静态资源，不能在运行时依赖 Google、gstatic 或 Google Fonts。每次 Web 发布后都要在真机网络环境检查首屏、中文字体和接口加载。
- 官网文案应保持“赛事观察、资料整理、个人复盘”定位，不使用保证中奖、稳赚、必胜、诱导投注或夸大预测能力的表达。
- 官网预约、账号或后台等能力若只存在浏览器 `localStorage`，必须明确视为前端临时能力，不得描述为服务器已落库或有运营后台。
