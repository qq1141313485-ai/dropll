## 已确认的产品规则

- App 第一版不做登录、支付、评论或用户自行上传，降低审核和运营复杂度。
- 计划内容统一显示由竞球镜助手上传；支持收藏、下载和下架。
- 不把演示内容伪装成线上真实数据；空数据、加载失败和正常列表必须分开显示。
- 计划首页关注最近更新，明确区分今日、昨日和历史更新；不把所有历史内容都写成“今日暂未更新”。
- 计划图片只使用已获授权的来源内容；保留来源水印，不去水印。
- 同一作者应长期归入同一计划，早场、晚场等时段词不能生成新的作者计划。
- 多作者文章不能长期依赖图片顺序；逐图识别应以低成本规则优先，OCR 只作为有限兜底。
- 未识别名称进入 `pending_name`，不得自动创建大量错误计划。
- 保存方案只保留最近 7 天、最多 200 条，仅本机保存，不做云同步。
- 已完场保存方案应展示具体中奖金额和命中/未中组合；赛果以官方 90 分钟口径为准。
- 选号与奖金计算属于信息计算工具，不出票；10000 倍是计算倍数，不代表真实票面。
- 第一版不提供拆票/拆单入口。
- App 不显示内部同步、抓取、缓存或数据源术语；异常提示必须面向普通用户。

## 已继承的技术能力

- 比分：Titan WebSocket 监听、数据库同步、官方数据回退、动态分钟和完场纠正。
- 比赛：列表、详情、历史赔率、分析资料、可选号权威校验和五分钟一致性巡检。
- 选号：混合玩法、单场与串关、胆码、复合过关、奖金优化、保存及完场结算。
- 计划：公开接口、管理后台、定时同步、名称治理、图片级分类、旧 ID 重定向和收藏迁移。
- 发布：iOS 使用 Swift Package Manager；Android、Web 和 iOS 共用 Flutter 业务代码。

## 冲突及最终取舍

1. **正式工程位置**
   Mac 的 `q/work2` 是历史分支；Windows `cai_tool_app_build` 是当前正式基线。

2. **计划演示数据**
   早期版本在无线上内容时显示演示数据，后期已明确删除。最终规则是不展示假数据。

3. **拆票功能**
   历史讨论和代码曾保留拆票模型，当前产品决定为第一版不显示拆票入口；内部兼容结构可暂留用于读取旧数据。

4. **实时数据过期提示**
   历史版本按 `titanLastUpdated` 两分钟判断并显示横幅，会因事件式推送产生误报。当前决定移除首页横幅，保留自动刷新和服务端巡检。

5. **多作者图片顺序规则**
   历史 `imageAssignments` 曾按图片位置分类，因每天图片数量和顺序不固定已停用。长期方案是规则识别优先、有限 OCR 兜底、人工审核异常。

6. **iOS 标识**
   历史 Bundle ID 为 `com.caimaster.caiToolApp`；当前统一为 `com.caimaster.jingqiujing`，Team 使用已登录 Xcode 的 `P5273P9N9W`。

7. **App 名称**
   产品仍以“竞球镜”为工作名称；备案因名称被驳回，新备案名尚未最终确定。备案名、软著名和上架名必须在提交前再次统一核对。
